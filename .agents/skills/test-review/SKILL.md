# XiHan.FormDesigner 测试审查

## 判断标准

每个测试给出「保留、改写、合并或删除」结论，并说明它保护的可观察契约。

- 保留：缺陷复发时会失败，覆盖公开 API、模板自检与问题码、取值校验、联动求值、编辑操作与逆操作、元素的属性 / 事件 / 方法、键盘与焦点、语言包。
- 改写：只复述实现、mock 后证明 mock、断言私有字段或内部状态名、依赖脆弱的 DOM 顺序、用固定延时碰运气。
- 合并：与相邻用例输入和断言等价，没有提供新的失败定位。
- 删除：不可能失败、只验证常量或快照自身，或已被更高层同等且更清晰地覆盖。

## 本仓专项

- 测试在 `form/packages/<包>/tests/*.spec.ts`，用 Vitest；core 是纯 TypeScript，用例不碰 DOM；runtime 与 designer 的用例文件头写 `// @vitest-environment jsdom`。
- 表达式求值在 core 与 runtime 的用例里用 `tests/fake-engine.ts` 的假引擎，只证明表单怎么调用引擎、怎么用结果；表达式本身的十进制语义归 `@xihan-ui/expression` 及其一致性用例，不在本仓重测。
- 编辑操作要同时断言结果与逆操作：无变化时返回同一文档引用、逆操作为空；失败抛 `FormOperationError`。
- jsdom 不证明真实布局、计算样式、浮层几何与动画；拖放、画布尺寸、`elementFromPoint` 一类要打桩，打了桩的用例只证明接线，不证明观感。
- 会抢焦点或自动开始引导的设计器用例，mount 时设 `autoTour = false`；断言 DOM 元素的先后顺序时比较文字或标识，不用 `toEqual` 比元素（它按结构比，两个不同元素也可能相等）。
- 先写会红的用例再改实现：审查新用例时，确认它在修复之前确实会失败。

输出按风险排序，附文件和行号。除非用户明确要求运行，否则以静态审查为主；不因缺少新测试自动修改代码。
